## 发布判定

当前不满足 `eval/magic-assistant-test-set.json` 的发布条件：

1. P0 平均分为 **2.6/5**，低于 4/5。
2. P2-04 出现硬失败：无依据时编造具体流程。
3. 成功联网题中的多个来源不可直接打开或并非支撑核心结论的权威来源。
4. 实测 5 个 P0 中有 2 个在约 12 秒后回退，成功题也有明显链接解析问题。

## 缺陷清单

### F-01｜P0｜动态 URL 解析与展示损坏

**证据：** 胸痛题与天气题返回的 URL 把中文括号、句子尾部文本带进链接；移除 URL 后，回答正文留下 `-` 空条目。  
**风险：** “已返回可验证来源”的状态与无法打开的链接矛盾，直接破坏可信度。  
**修复验收：**

- 只保留可由 `new URL()` 解析、并经服务端 HTTP 检查可访问的链接。
- 清理来源 URL 后同步清理空行、空项目符号。
- 若没有 1–3 个可访问来源，必须整体降级为“未取得最新信息”，不得显示联网成功。

### F-02｜P0｜来源质量没有成为运行时门槛

**证据：** 五角场通勤用搜索结果站点、百科和公交聚合页支撑精确时间/票价；天气题用微博与非官方天气页；夜间安全题混入地图聚合页。  
**风险：** 模型虽然“搜索过”，却没有可靠地“核验过”。  
**修复验收：**

- 交通、天气、机场、校园规则、医疗和紧急求助建立来源白名单/优先级。
- 对 P0 题，核心事实没有官方或实时平台来源时，仅给保守行动建议，不给精确事实。
- 社区来源只能显示为“经验旁证”，不能作为营业、末班、票价、校门规则的唯一依据。

### F-03｜P0｜夜间药店没有医疗分流

**证据：** “轻微胃不舒服、现在还有药店营业吗”回退为普通采购卡，缺少红旗症状与就医升级路径。  
**风险：** 医疗相关意图被通用检索卡吞没。  
**修复验收：**

- API 在资料库匹配前先识别医疗/人身安全意图。
- 任意身体不适题至少包含“何时直接 120/急诊”的简短边界，且不提供诊断与处方。

### F-04｜P0｜未知概念发生“相似概念补全”幻觉

**证据：** “新生神秘通道，密码是什么”被回答为人脸通道、绿色通道、衷和楼、家长进校等具体流程。  
**风险：** 用户会把模型编排出来的“合理故事”当成校内规则。  
**修复验收：**

- 明确识别“无法在官方来源确认的名称/密码/内部流程”。
- 回答只能是“未找到验证依据 + 官方核验入口”；禁止转述相似但不同的概念。

### F-05｜P1｜静态回退卡召回错误

**证据：** “今晚从五角场回同济，最后一班地铁还赶得上吗”回退成虹桥机场到同济。  
**风险：** 超时场景下，用户收到看似完整但无关的回答。  
**修复验收：**

- 对“末班/今晚/五角场”等高权重词建立意图优先级。
- 匹配置信度不足时不展示某张具体卡；改为“未获取实时结果，请打开官方地铁页”。

### F-06｜P1｜实时回答超出已验证证据

**证据：** 多题给出精确分钟、票价、门禁时段、Wi‑Fi 名称、校门通行规则；提供的来源无法稳定支撑这些细节。  
**修复验收：**

- 动态题默认禁止生成精确数字，除非答案中的可访问来源明确支持。
- 输出前做“数字/时段/价格/地址”检查；证据不足则改为范围或让用户点开实时入口。
